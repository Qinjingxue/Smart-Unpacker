# 测试改造计划 · 第 6 条：加密分卷部分卷名混乱但卷号标识完整

对应 `tests/测试改造.txt` 的第 6 条：

- 加密 zip / rar / 7z 各种形式分卷压缩包、SFX 分卷压缩包；
- 部分分卷文件后缀混乱但文件名（stem）相同，混合在同一个目录；
- 卷号标识（`.001` / `partN` 等）不被破坏、只是前后有无效数据时，
  项目应能识别出这些加密分卷并正确解压。

## 与第 2 条的区别

- 第 2 条把全部分卷统一改成某一种命名（含伪装命名）；
- 第 6 条在同一个目录里混合“标准名卷”和“混乱名卷”，每个场景只动部分卷；
- 目录里还放入同 stem 的 `*.notes.txt` 与无关 `.bin` 干扰文件，验证分组精确性
  （干扰文件不得成为成员）。

## 混淆场景（卷号标识始终完整）

1. `suffix-junk-some`：偶数卷在卷号标识后附加 `.junkNN.tmp`，头卷保持标准名；
2. `suffix-junk-all`：每个数据卷都附加各自的后缀无效数据；
3. `prefix-suffix-junk-all`：每个数据卷在卷号标识前后都附加无效数据
   （前缀统一为 `noise.`，保证 stem 一致）。

SFX 约定：7z/zip 的 `.exe` 只是启动器（不含数据），保持标准名，混淆只作用于
数据卷；rar 的 `part1.exe` 本身就是数据头卷，与其他卷一样参与混淆。

## 文件

- `plan6_support.py`：混淆场景定义、改名与断言（复用 plan2 的 100 密码列表与
  plan1 的检测/解压断言）。
- `test_plan6_split_confusion.py`：7z/zip/rar 加密普通分卷 × 3 场景。
- `test_plan6_sfx_split_confusion.py`：加密 SFX 分卷 × 3 场景。
- `test_plan6_mixed_directory.py`：`release`（7z）与 `album`（rar）两组加密分卷
  各自部分混乱、混合在同一个目录，分别识别并解压。

每个用例 420KB 载荷、100KB 分卷，得到 5~6 个分卷；密码列表 100 个
（99 个错误 + 正确密码），验证识别分卷与识别密码同时成立。

## 当前状态（已知失败自动记录到 `tests/real/error_records/`，待统一修复）

- 7z / zip 普通分卷：3 个场景全部通过——部分或全部卷带无效后缀时，5 个成员
  全部被识别、正确密码从 100 个列表中命中并完整解压。
- 加密 rar 普通分卷：3 个场景全部失败——只有“标准 `partN.rar` 名”的卷会被
  按命名归组（`suffix-junk-some` 只归到 part1/3/5 共 3 个；全部装饰的场景只
  识别出结构可确认的头卷 1 个），带无效后缀的卷不参与分组。与 plan2 已记录的
  “加密 RAR 分卷 + 伪装命名只识别出 1 个成员”同源：加密头无法做结构确认时，
  命名兜底不识别装饰卷名。
- SFX 分卷：7z/zip/rar × 3 场景全部失败——检测命中启动器但成员数只有 1，
  数据卷（即使标准名）未并入分组；与 plan1/plan2 已记录的 SFX 分卷检测缺口
  同源，与本次命名混淆无关。
- 混合目录用例：7z 组检测与解压通过；rar 组同样因装饰卷名未参与分组而失败。

修复方向（供后续阶段参考）：加密分卷（尤其 rar）的命名兜底应把“卷号标识完整、
前后有无效数据”的卷名纳入同一分组；SFX 分卷需要把 `.exe` 启动器与
`.001` / `partN` 数据卷正确关联。
